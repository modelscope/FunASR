Why can a millisecond timestamp still seek to the wrong word?

2026-06-23 published · Revised 2026-11-23 · Speech technology explained

You transcribe an interview and make each word clickable. The text looks right, but clicking it plays half a sentence too early, or sends you back to the beginning. It is tempting to blame the model. First check three simpler possibilities: the player expects seconds but receives milliseconds; the interval belongs to a short segment rather than the whole recording; or the displayed words have changed while their timestamps have not.

This guide answers one question: is a timestamped transcript ready for click-to-listen navigation? You will learn to identify the audio timeline, the text units each interval belongs to, and what still needs listening-based review. This is a conceptual guide, not an installation tutorial. All numeric examples are invented, not measured model outputs.

In this guide: Choose an output path · Units and accuracy · Match the text · Restore the timeline · Review the result · Agent record contract

1. What will your recognition path actually return?

FunASR is a toolkit that coordinates model calls and processing. Fun-ASR and SenseVoice are model families, whose specific capabilities depend on the checkpoint and invocation. FunClip is a transcription and editing application. Model weights, an installed Python package, an independent runtime and a network service are different layers. Producing text does not imply that every runtime returns character-level timestamps, or that all outputs use the same fields and units.

For fine-grained navigation, choose a model and runtime whose documentation supports the required output, then inspect what your call actually returns. In the pinned Paraformer Python implementation, timestamp calculation is conditional: it reads pred_timestamp, falling back to output_timestamp when the former is not supplied. A Paraformer name alone is therefore not a dependable promise of timestamp output. These parameters are not universal switches for other models.

If you only need readable text, start with your first recording-to-text task. Captions also need suitable sentence breaks, display duration and layout; precise editing also needs listening-based boundary checks. Timestamps are inputs to those applications, not a guarantee of finished-caption or finished-edit quality. This article does not rank recognition accuracy or apply one model's license to the entire ecosystem.

2. Milliseconds describe the scale, not the measurement error

For an interface explicitly using milliseconds, [1200, 1500] means 1.2 to 1.5 seconds, a span of 0.3 seconds. Writing an integer down to the millisecond tells you how the number is represented. It does not establish that the real speech boundary is accurate within one millisecond. More decimal places in a map coordinate do not make the location equally precise.

Speech is not a sequence of neatly separated blocks. Connected sounds, pauses, breath, background noise and overlapping speakers can make a word boundary ambiguous. Correct words and edit-ready timing are separate properties. Incorrect words can also make their alignment difficult to interpret. A recognition error rate is not a substitute for a timing-error measurement.

This Paraformer path estimates locations using prediction signals related to CIF, or Continuous Integrate-and-Fire. Intuitively, weights accumulate along audio frames; reaching a threshold provides a location cue, and postprocessing organizes those cues and text units into spans. This is not a stopwatch pressed at every spoken character. The implementation also includes time conversion, shifts and long-gap handling. Treat its output as estimated boundaries from a particular implementation, not as human-annotated ground truth.

VAD, or voice activity detection, answers where speech may occur; it does not align every word. Dividing a speech interval evenly by the number of displayed characters creates an artificial schedule, not model-measured word timestamps. Save any timing created for presentation separately from the original estimates.

3. Which text does each interval belong to?

Splitting displayed text on spaces and pairing the pieces with timestamps is convenient, but only valid after the two units have been defined. A Chinese unit may be a character; an English word may combine several subwords; abbreviations, numbers and symbols may be transformed. A token is a unit used by a model or tokenizer, not necessarily one visible character or one word.

The pinned text postprocessor filters selected special symbols, merges subwords marked with @@, and handles abbreviations. When timestamps are provided, it also processes their indices and intervals. The relationship among displayed text, processed words and timestamps follows that implementation; a consumer should not reconstruct it by guessing from character counts.

Consider the invented display string “OpenAI，您好！” It contains English, Chinese and punctuation, but says nothing about how many units the model originally used, whether the comma has its own span, or whether the English text has already been merged. Removing spaces, adding punctuation or rewriting numbers changes the display again. Matching list lengths is a minimum check, not proof of correct semantic alignment.

Python's ordinary zip silently stops at the shorter input. It will not warn you that trailing words disappeared, and it cannot detect a shift in the middle. First establish the selected version's text-unit-to-interval contract, retain the matching original outputs, verify their correspondence, and only then build a display layer. When the correspondence is missing, report that reliable alignment is unavailable. Do not truncate, insert zeroes or divide the duration evenly to manufacture success.

Keep manual corrections separate from the original recognized text. Original spans may still offer useful sentence-level listening entry points, but they do not automatically become verified boundaries for every corrected word. Aligning a supplied transcript to audio is generally called forced alignment; it is not the same task as recognizing the words again. Check support in the specific tool you intend to use.

4. Is the timestamp relative to a segment or the recording?

Suppose a segment starts 30 seconds into an interview and contains [1200, 1500] milliseconds. If those numbers are segment-relative, the original-recording interval is [31200, 31500] milliseconds. If the output is already recording-relative, adding 30000 again introduces a second offset. These three invented conversion examples all start with segment-relative inputs:

Segment originLocal intervalRecording intervalPlayer start
0 ms1200–1500 ms1200–1500 ms1.2 s
30000 ms1200–1500 ms31200–31500 ms31.2 s
60000 ms250–750 ms60250–60750 ms60.25 s

The arithmetic has two steps: recording milliseconds = segment origin milliseconds + local milliseconds; divide by 1000 for a player that expects seconds. The difficult part is determining which steps already happened. FunASR's model and AutoModel composition paths include offset handling. The presence of VAD is not a reason to add an offset unconditionally. Use the contract of the exact version and invocation you are running.

If you remove several pauses and concatenate the remaining audio, the new file's timeline generally cannot be converted back with one constant offset. Preserve a mapping of each retained segment's old and new positions, then convert within the appropriate segment. The edited audio and total removed duration alone lose the information needed to locate the original recording.

Do not guess units from plausible-looking numbers. Confirm the field definition before checking against recording duration. A factor-of-1000 error, every segment restarting at zero, or drift that grows later in the recording are useful diagnostic clues, not permission to automatically change values.

5. When is it ready for click-to-listen?

  1. Check structure. Required fields exist, endpoints are finite, and the units and timeline are known. End must not precede start. Flag negative values, out-of-range intervals, suspicious zero-length spans and ordering problems. Preserve them instead of silently dropping them. Set any rounding tolerance in advance, not after seeing a failed check.
  2. Check text correspondence. Apply the selected runtime's unit definition and retain original text and intervals. Include the mixed languages, numbers, abbreviations and punctuation that your actual application encounters, rather than only a short, simple sentence.
  3. Listen. Use recordings you are authorized to process. Check the beginning, ending, segment joins, long pauses and important phrases. Does clicking play the intended content? Does a proposed cut remove an onset or word ending? Record observed errors and failures, not just whether the arrays are populated.

A reading-oriented player may deliberately seek slightly before the target and clamp its playback position to valid limits. That is a product decision, not a correction to the model's original boundaries. Word highlighting, captions and fine editing need different tolerances; an unexplained “precise” label cannot serve all three. Preserve original estimates separately from derived display or playback positions.

For missing timestamps, check support and invocation settings. For unknown units, stop conversion. For mismatched text, inspect the postprocessing path. For a global shift, inspect segmentation and editing records. Rerunning the same input does not fix a coordinate-system or contract error. To create captions next, see SRT/VTT generation and listening-based review.

6. For Agents: preserve provenance instead of guessing boundaries

This is a suggested application-side record, not a universal FunASR SDK response. input_path is a user-authorized absolute local audio path string; input_sha256 identifies that file. Record exact model_revision and runtime_version values, not “latest.” Changing models or runtimes requires rechecking fields, units and text-unit definitions.

  • Original output: raw_text is the original recognized string; raw_timestamp retains original intervals in order. Use null when missing, never fabricated spans. Keep the original response separately. Corrections and presentation text must not overwrite it.
  • Time contract: time_unit is explicitly ms or s; timeline is segment or recording. If unknown, record that state and stop deriving locations. segment_offset_ms is a finite nonnegative origin in recording milliseconds. Use null when no segment mapping exists, not an assumed zero. Add the offset once only for confirmed segment-relative inputs.
  • Derived records: retain which original unit or interval each display unit came from and every transformation applied. Milliseconds-to-seconds conversion changes units only. Save presentation adjustments separately and retain listening-review status: valid structure does not prove accurate timing.
  • Failure: status is ok or error; error explains missing fields, unknown coordinates, uncertain correspondence or invalid bounds. A batch runner must retain failed items and return a nonzero exit code, not claim that partial output is complete. Do not automatically retry deterministic contract errors. Retry temporary transport failures only within a previously authorized limit and retain each attempt.
  • Authorization: reading this article requires no model download. Running a model adds separate software-installation, initial-weight-download and license checks. Later disconnected operation requires all dependencies, configurations and weights, plus a verified path that will not fetch missing files. Audio uploads, paid services, overwriting originals and actual edits require appropriate authorization; “timestamp calibration” does not broaden data permissions.

Keep three questions in view: What unit is this number in? Which audio timeline does it use? Which text unit does it describe? Answer those, then listen to verify the intended use. That is what makes a timestamp useful navigation data.
