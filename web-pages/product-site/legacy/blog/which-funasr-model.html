FunASR 模型怎么选？先说清你要交付什么

2026-06-23 发布 · 2026-11-19 修订 · 入门选型

你想把一段采访做成字幕，搜索后却遇到 FunASR、Fun-ASR、SenseVoice、Paraformer、FunClip，还有 PyTorch、ONNX、vLLM。到底要装哪个？先别按“最大”“最快”挑名字：这里既有工具包，也有模型、运行时和应用，它们不是同一层的替代品。

这篇不要求安装软件。读完你要得到一份选型单：输入什么音频、需要什么结果、选哪条处理路径、还要验证哪些条件。先把任务说明白，再进入安装教程，能少走很多弯路。

1. “把声音变成文字”其实有好几种任务

假设采访里有人说：“下周三寄三套样品。”识别出这句话，只完成了语音识别（ASR）。如果你要把它放进视频字幕，还需要知道字幕何时出现、何时消失；如果两个人轮流说话，还需要把片段分配给不同说话人。这些结果不能从“有文字了”自动推出来。

  • 文字：说了什么。适合搜索、复制和整理笔记。
  • 时间戳：文字或片段在录音中的起止位置。词级、字级和整段时间戳不是同一种精度。
  • 说话人标签：哪些片段可能属于同一个人。匿名的 Speaker 0 不等于“张老师”，也不保证在另一份录音中仍指向同一个人。
  • 流式结果：声音还在输入时就返回部分文字。一个能处理完整文件的模型，不因此就具备相同的流式接口。

两个经常被混淆的组件也值得先认识：VAD寻找有人说话的时间区间，但不负责识别每个字；标点模型帮助给文字断句，但句号不是字幕时间轴。选型时先把必需的输出圈出来，不要先把所有组件都装上。

2. 四个项目，各负责哪一层？

名称它是什么何时从这里开始
FunASR语音工具包及配套运行、服务代码。Python 安装包名是 funasr。在自己的程序里组合识别、VAD、标点或说话人处理，或了解部署入口。
Fun-ASR模型系列及其模型侧集成。Nano 与 MLT-Nano 是不同的 checkpoint，即需要分别选择的模型权重与配套文件。了解这些模型的语言范围、权重格式和对应推理入口。
SenseVoice语音理解模型系列。本文讨论具体的 SenseVoiceSmall。考虑转写，以及它提供的语种、情绪和音频事件标签。
FunClip面向音视频转写、字幕和剪辑的应用。希望先使用剪辑工作流，而不是自己搭建全部界面。

pip install funasr 安装的是程序，不会把全部模型权重都装进电脑。权重是模型学习得到的参数文件；运行时是实际加载权重、执行计算的软件。一个模型可以有不同格式的权重，但它们不能随意互换。HTTP 服务又是额外的一层：它接收请求、调用推理程序并返回结果。

因此，“把应用接到一个现成语音 API”和“在本机安装模型”是两件事。使用远程服务可能上传音频并产生费用；本地运行通常需要提前下载软件和权重。FunASR 工具包的 MIT 许可也不代表所有模型权重、数据与外部服务都采用同样条款。

3. 用四个问题缩小选择

问题一：音频里是什么语言？

不要只写“中文”或“多语言”。普通话、粤语、日语，以及夹杂产品英文名的普通话，是不同的测试条件。先核对具体 checkpoint 的语言说明，再用有代表性的录音验证。模型卡列出某种语言，不等于你的口音、噪声和领域词已经测过。

问题二：你最终要文字、字幕，还是剪辑结果？

只要文字，可以先走最简单的文件转写路径。要字幕，就核对所选模型和接口能否返回所需粒度的时间戳，以及如何导出字幕。要“按某个人的发言剪辑”，还需说话人处理和应用层选段逻辑。不能把缺失的时间戳平均摊到每个字上，再声称是模型对齐结果。

问题三：录完再处理，还是边说边出字？

“离线文件识别”常指拿到完整音频后处理，不等于运行时绝不联网。真正断网还要求依赖、权重、配置和相关资源均已准备好，并验证没有外联依赖。直播字幕则要单独选择流式 checkpoint 或明确支持该工作流的服务，检查部分结果、结束信号和会话状态。

问题四：机器和数据权限允许什么？

记下操作系统、可用内存、CPU，以及 GPU 型号和显存（如有）。CPU 能加载模型，不代表能在你的机器上实时运行；有 GPU 也不代表软件已配置好。再确认录音能否离开本机、是否允许下载权重，以及用途是否符合模型条款。这些条件会先排除一批不适合的方案。

4. 常见候选：看能力边界，不排“万能第一名”

普通话文件转写，兼顾时间戳或热词：检查 Paraformer 路径

Paraformer 是模型系列，不是一个覆盖所有接口的开关。FunASR 文档提供 paraformer-zh 的中文转写路径，并说明时间戳、热词等用法；是否能在你选的安装包、模型版本和服务接口中使用，仍要逐项核对。流式路径使用不同的 paraformer-zh-streaming，不能拿离线模型名称代替。

转写之外还需要声音标签：检查 SenseVoiceSmall

官方文档列出的 SenseVoiceSmall 识别语种是普通话、英语、粤语、日语和韩语，并提供情绪与音频事件标签。它不是“任何语言都可以”的通用承诺。情绪标签是模型预测，不是对说话人真实心理状态的判断；标签也不是说话人身份。

若采用 SenseVoiceSmall + FSMN-VAD + CAM++ 的组合，VAD 找语音区间，CAM++ 提取说话人特征，FunASR 管线再聚类分配匿名标签。这是多个组件配合，不是 SenseVoiceSmall 单独完成了全部功能。如果需要保留原始声音标签，还要核对后处理和服务是否把它们去掉。

评估 Fun-ASR：先选 checkpoint，再选加载方式

基础 Fun-ASR-Nano 与覆盖 31 种语言的 Fun-ASR-MLT-Nano 是不同 checkpoint。基础 Nano 的官方说明面向中文、英文、日文及所列中文方言和地域口音；不要把 MLT-Nano 的语言范围搬到基础 Nano 上。

同样要区分原始 FunASR 权重、原生 Transformers 的 -hf 导出，以及 GGUF 或原生 vLLM 的对应产物。文档中的 CPU、CUDA、原生 Transformers 和 vLLM 路径各有加载与依赖要求，不能只改一个 model 字符串就假定完成迁移。更不能把某一路径的测速或功能直接套到另一路径。

目标是操作视频：从 FunClip 应用工作流入手

如果产物是字幕或剪辑片段，先检查 FunClip 提供的工作流是否符合需求，再核对它实际调用的识别后端。应用支持导出某种文件，并不代表每个后端都能提供相同的时间戳或说话人信息。启用外部大模型辅助剪辑前，还要明确会发送哪些数据、使用哪个服务以及是否收费。

5. 写一份能指导下一步的选型单

下面是一个假设任务，不是已经跑出的识别结果：你有一段获得处理授权的普通话访谈，想先得到可搜索文字；当前只有 CPU，音频不能上传到外部服务。

  • 输入：本地访谈音频；普通话；先挑有权使用的短片段，包含人名、数字和句尾。
  • 第一阶段产物：本地 UTF-8 转写文件。不在这一步承诺字幕时间轴或说话人身份。
  • 候选入口：FunASR 工具包的 Paraformer 中文文件转写路径，先参考下方入门教程；它是候选，不是已证明最优的模型。
  • 允许的操作：确认条款后下载指定软件和模型；不上传录音，不启用收费服务，不覆盖原文件。
  • 通过标准：能得到本次生成的结果文件，并回听核对关键内容；同时记录本机耗时和内存是否可接受。
  • 下一阶段：短片段通过后再检查长录音覆盖；如果新增字幕或按人剪辑需求，重新补齐时间戳和说话人条件。

这比“给我找一个最强模型”更容易执行。若候选不满足要求，保留失败样本和原因，再比较另一个候选；不要只展示识别得最好的几段。

给 AI Agent：把选型单当需求，不当 API 参数

上面的条目是人和 Agent 之间的任务说明，不是 FunASR SDK 的配置字段。执行前必须从所选版本的文档映射到实际命令或函数参数。

  • 输入约定：记录音频的真实路径、格式、声道数、采样率（Hz）和时长（秒）；未知值先检查，不根据文件后缀猜测。路径示例不是可直接读取的真实文件。
  • 模型约定：记录完整模型 ID、revision 或校验值、权重格式、运行时及软件版本。服务中的短别名不一定是可用于下载的模型 ID。
  • 输出约定：先约定文件路径、文字编码及所需字段；若需要时间戳，明确单位和粒度；若需要说话人，明确标签只在当前录音内使用。不捏造后端没有返回的字段。
  • 权限约定：下载、外部上传、远程代码、付费调用和覆盖已有结果均不得从“做转写”中默认为已获许可。缺少授权时先停止对应操作。
  • 失败约定：以实际程序的退出码或接口错误判断执行失败，不把旧输出当新结果。保存错误，修正原因后再按约定有界重试；不自动换模型、开并行副本或转向外部服务。

6. 怎样知道自己选对了？

先验证能不能完成任务，再比较质量和资源开销。用有权处理、能代表实际工作场景的音频，覆盖清晰语音、噪声、专名、数字和容易遗漏的结尾。多人或字幕任务还要回听检查轮次与时间边界。一次干净示例成功，只是起点，不是完整质量评测。

比较不同模型时，使用同一份输入和事先确定的核对方式。文字通顺不等于忠实于录音；只报一个 CER/WER 数字，也无法替代对数据、归一化规则和测试范围的说明。速度记录应区分下载、加载与识别时间，并注明硬件和批次，才有比较价值。

本文是依据官方文档整理的选型解释，没有新增模型推理、准确率、实时性或容量测试。因此不提供跨模型性能排名，也不声称下列所有路径都在同一环境实测通过。
