speaker 0 是谁？读懂说话人分离的结果

2026-06-17 发布 · 2026-11-21 修订 · 语音技术入门

会议转写里出现了“speaker 0：这个方案我来负责”。你知道文字是什么，却还不知道该把任务交给谁。说话人分离帮你把声音相近的发言归到一组，但它并没有读过参会名单。把编号直接换成某个人的名字，可能让一份看起来整齐的纪要写错责任人。

读完这篇，你应当能解释编号的含义，判断一句话的说话人标签能证明什么，并整理出保留录音位置、匿名编号和复核状态的转写记录。本文是概念与结果阅读指南，不需要安装软件；示意对话和时间数字均为人为构造，不是真实模型输出。

1. 先分清：分组不是认人

语音识别（ASR）回答“说了什么”；说话人分离（speaker diarization）尝试回答“哪些时间段由同一个说话人发出”。这里的“谁”通常只是录音内的匿名分组，不是姓名、账号或员工编号。已登记人员的身份匹配则需要另外的登记样本、匹配规则、阈值评估和授权，不能从一个聚类编号里推出来。

可以把它理解成给录音贴彩色标签：同一种颜色表示系统认为这些片段属于同一组，但颜色并不知道人的名字。一次分组还可能把同一个人拆成两组，或者把不同人合到一组。因此，三个编号不等于已经证明有三个人，文字流畅也不等于归属正确。

在这套生态里，FunASR 是工具包，负责组织识别、VAD 和说话人处理等组件；Fun-ASR、SenseVoice 是模型系列，具体能力要看 checkpoint 和调用路径；FunClip 是转写与剪辑应用。在本文讨论的 FunASR 组合管线中，CAM++ 提供说话人向量，后续聚类产生编号。SenseVoice 的情绪标签不是说话人身份。官方输出类型说明把向量、匿名编号和身份匹配分开列出了。

2. 读一个小例子：同一录音里的 0、1、0

假设有一段九秒钟的对话，系统给出下列简化记录。这里的文字、时间和标签都只是教学示例，省略了真实响应中的其他字段。

区间（毫秒）spk文字示意
[0, 3000]0我们先确认需求。
[3000, 7000]1我补充一下交付时间。
[7000, 9000]0好，那继续讨论。

你可以读成：“系统把第一段和第三段归为同一组，把第二段归为另一组。”不能读成：“第一段是主持人，第二段是产品经理。”这条实现会按遇到标签的顺序重新编号，但这种排序不提供身份信息，也不保证换一次裁剪、换一套管线后编号仍相同。参见编号重映射实现。

应用可以用 (recording_id, spk) 保存这次运行中的分组，再另存人工确认的显示名；这两个字段的组合是应用设计建议，不是新增 SDK 字段。重新运行或改变模型、切分方式后，也要区分运行版本。两场会议都出现 spk=0，不能据此把它们合并到同一个人的历史档案。

3. 一句一个编号，不代表整句只有一个声音

“一句话”是转写的组织单位，“一次换人”是声音的变化，两者未必在同一位置。有人插话时，标点可能还没断句；VAD 找到的语音区间也可能包含不止一个人。把整句标成一个编号，是一种归属规则，不是把混合音频里的每个人都单独分离出来。

本文所查版本的 distribute_spk 会累计每个说话人区间与句子的重叠时长，选择累计重叠最多的编号。它会先把内部说话人区间的秒转换成句子使用的毫秒；时长相同时保留先遇到的重叠编号。参见句子归属源码。

再做一个假设：一条句子记录覆盖 0–8 秒，编号 0 覆盖前 3 秒，编号 1 覆盖后 5 秒。按上述规则，这条句子会标成 spk=1。这并没有证明前 3 秒也是编号 1 说的，更不能把句中每个词都无条件归给同一个人。

还有一个容易忽略的边界：这个函数在没有任何重叠时也默认写入 0。因此，单看 spk=0 无法区分正常分组和这一回退分支；它不是“已确认”，也不是置信度。需要更严格的业务保证时，应保留可用的时间依据并复核，不能把所有 0 自动改成“未知”，也不能把它们都当作可靠身份。

4. 把结果整理成可以负责的会议记录

如果目的是做纪要，先完成下面这条闭环，再给发言绑定负责人：

  1. 保留原始录音位置和原始结果。 给录音分配应用内编号，记录使用的模型版本、工具包版本和运行配置。不要只留下“张老师说了什么”的最终文本。
  2. 先显示匿名编号。 让每段文本能回到原录音的起止位置。回听发言开头、交接处、短插话和抢话处，检查漏分、错分以及一句跨多人的情况。
  3. 另外记录人工确认。 确认后再设置显示名，保留原编号和修订记录。没有把握就保留匿名或标注待确认，不从“我来负责”等文本内容猜名字。
  4. 检查业务产物。 导出纪要或按人选段前，抽查同一编号的多个不相邻片段。任务、承诺和争议性发言尤其需要回听，不只看页面是否有整齐的说话人列。

成功判据是“关键发言能追溯到录音，未确认的归属不会伪装成姓名”，不是“输出恰好有几个编号”。有意保留待确认项，比把错误名字填满表格更有用。若需要按匿名说话人选段，可继续阅读多人录音的字幕与剪辑指南，并核对它使用的独立后端。

5. 选管线时，要一起看文本和时间依据

FunASR 的通用说话人聚类位于 VAD 管线中；只配置一个说话人模型，不等于所有直接识别入口都会返回分离结果。带字词时间戳的识别结果与没有这类时间戳的结果，组织句子的方式也会不同。所查实现会在缺少相关条件时从标点分段回退到 VAD 分段，不能把“换一个 model 名称”当成输出语义不变的保证。具体分支见AutoModel 的说话人处理路径。

如果只需要文字，先完成普通转写；如果需要带匿名编号的长录音结果，可比较组合管线和提供联合转写、分离能力的独立后端。第三方 MOSS-Transcribe-Diarize 是另一条路径，不需要再照搬本文的外部 VAD/说话人组合，具体环境、权重、许可和输出遵循它自己的指南。参见官方任务选型表。

安装 funasr 软件包不等于已备齐识别、VAD、标点和说话人组件的权重。首次获取模型需要明确下载来源、版本、许可与网络条件；后续离线运行需要完整本地快照和已安装依赖，并验证所选加载路径。本文不提供一条适用于全部模型、CPU/GPU 或服务的安装命令，也不承诺 CPU 实时性能。

6. 给 Agent 的接入边界

以下是应用侧的读取规则，不是要求所有运行时返回相同 JSON。先确认调用的是哪条管线，再解释字段：

  • 标签：本文通用 SDK 管线的 sentence_info[].spk 是整数匿名编号，不是名字或概率。单独调用说话人模型得到的向量也不能代替这个编号。
  • 时间：本文 sentence_info 的 start/end 以毫秒表示，参考输入录音时间轴；读取前检查数值有限、起止有序且不超出录音范围。不要把 HTTP 服务常用的秒直接代入；裁剪后应按实际裁剪偏移还原原时间轴。
  • 缺失：缺少 sentence_info、空列表、缺少 spk 是不同情况。检查调用路径、有效语音、时间戳和日志；不要补造编号、姓名或置信度。text、sentence 等文本字段也应按对应版本的实际返回检查，不能仅凭别的教程假定存在。
  • 数据授权：下载新权重、上传会议录音到服务、登记声纹样本或把编号映射为真实姓名，都要先确认授权、保存期限与访问范围。匿名编号不意味着原录音已经匿名化。
  • 失败与重试：输入、依赖或接口不匹配时停止并报告原因；不要反复运行直到出现“想要的人数”。只有明确的临时故障才按应用预设上限重试，保存原始结果且避免重复上传。

读完后，用三个问题检查自己

两场会议都有编号 0，能认定是同一个人吗？不能。一个长句被标成 1，能认定句内没有插话吗？不能。拿到了说话人向量，能直接填上姓名吗？仍然不能。先分清“声音分组”“文本归属”“身份确认”，才知道应用还缺哪一步。

依据与范围：本文依据上面固定版本的官方源码和文档解释字段、编号重映射及归属规则，检查了示意数字与双语页面。没有运行新的声学模型推理，也没有验证会议识别准确率、说话人数或身份匹配效果；其他 checkpoint、旧安装包和服务需单独核对。

下一步：还没有转写结果，先看第一段录音转文字；需要决定模型与接口，阅读按任务选型；如果你困惑的是裁剪与字幕时间，接着读VAD 区间与时间轴。
